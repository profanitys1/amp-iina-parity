# Verified IINA look spec for AMP

Audited: `docs/research/2026-10-13-gemini4-argon-iina-look.md` (Gemini).
IINA tree: `.../scratchpad/iina-src/iina` at git HEAD `fbcff4df` (read only). Paths below are relative to `iina/iina/`.
AMP tree: `Aagedal Media Player/`. AMP deploys to macOS 26 only (CLAUDE.md), so every "macOS 15 or older" branch in Gemini's text (radius 6, `.popover` NSVisualEffectView) is irrelevant and omitted here.

Legend: CONFIRMED = value matches source. WRONG = value differs, true value given. NOT IN SOURCE = Gemini invented it or it is OS behaviour that source does not state. UNVERIFIED = left out of the implementable spec.
Gemini's line numbers are almost all off (it cites `MainWindowController.swift:16` for `UIAnimationDuration`, real line 22). Where the value is right and only the line is off, I mark CONFIRMED and give the real line.

## 0. Findings that change the plan

1. **The "2 pt scrubber-row gap" change is WRONG; do not make it.** IINA's `TimeLabelOverflowedView`/`TimeLabelOverflowedStackView` inset their alignment rect by 6 top (`TimeLabelOverflowedView.swift:23`, `TimeLabelOverflowedStackView.swift:13`). Layout is `spacing(.top(8))` then `playSlider.padding(.vertical(6))` inside that inset view (`OSCFloatingView.swift:49-50`, `MainWindowController.swift:600`). So the slider top sits 8 + 6 = 14 pt under the button row, which is exactly what AMP's `VStack(spacing: 8)` plus the scrubber's own 6 pt vertical padding gives (`PlayerScrubber.swift:15,91`). AMP card = 14 + 24 + 8 + 27 + 8 = 81 pt, and the installed IINA measures 80 pt (`docs/IINA_OSC_REFERENCE.md`). Changing to 2 pt would give 75 pt and break parity.
2. **The "~67 pt height" is a hard-coded clamp constant, not a layout result** (`OSCFloatingView.swift:117`). Gemini's arithmetic (14+24+8+27+8-6) is 75, not 67, and "27" is not in source. Rendered height is about 80.
3. **IINA's default OSC vertical position is 10% of video height above the bottom, not flush.** `controlBarPositionVertical` default `0.1` (`Preference.swift:1068`); `yConstraint.constant = videoHeight * cpv` (`OSCFloatingView.swift:78-88`). AMP's "flush with bottom, 0 pt gap" (`OSCPosition.swift:13-19,32`, `docs/IINA_OSC_REFERENCE.md`) was measured from a user-modified install: `defaults read com.colliderli.iina controlBarPositionVertical` on this machine returns `0`, and horizontal returns `0.5035`. Default parity therefore means 10% (e.g. 36 pt in a 360 pt window).
4. **AMP cannot drag vertically across the video.** `ContentView.swift:464` wraps the card in `.frame(height: 120)`, so vertical position is a fraction of a 120 pt strip, measured from the top of that strip (`OSCPosition.origin`, `PlayerScrubber`/`FloatingOSCView.swift:239-242`). IINA stores the fraction from the bottom of the whole video container, clamped by `yMargin 25` at the top (`OSCFloatingView.swift:116-124,161`). Stored values are not interchangeable.
5. **OSC auto-hide while paused:** CONFIRMED that IINA hides it. `createTimer()` (`MainWindowController.swift:2158-2162`) has no play-state check; `mouseMoved` calls `updateTimer()` unless the pointer is over `currentControlBar` or `titleBarView` (`:1297-1310`). AMP gates on `isPlaying()` at `PlayerOverlayController.swift:138` and `:144` (Gemini says `:100`, wrong). Removing the gate is a product decision for the planner; the evidence supports it.
6. **OSD "colon split" drops the colon.** `defaultAttributedString` uses `string.split(separator: ":", maxSplits: 1)` (`OSDMessage.swift:49`), so `"Volume: 80"` renders as `Volume` (18 pt secondary) + ` 80` (20 pt primary). Gemini says the suffix keeps `": ..."`; wrong.
7. **Chapter cut-outs on the play slider only draw when `showChapterPos` is on, default `false`** (`PlaySliderCell.swift:36,130`, `Preference.swift:1095`). Gemini presents them as always on.
8. **Five-button toolbar does not shrink to 20 pt in the main window.** `setupOSCToolbarButtons` passes `reducedWidth: false` (`MainWindowController.swift:919`); `compactFrameWidth` is otherwise unused.
9. **`AccessibilityPreferences.adjustedDuration` follows the "Disable animations" preference, not Reduce Motion** (`AccessibilityPreferences.swift:16-18`). Gemini's token file claims Reduce Motion. Reduce Motion only switches the sidebar from slide to fade (`SidebarController.swift:258-261`). The OSD fade-out is not adjusted at all (`MainWindowController.swift:2283`).
10. **A local IINA is installed** (`/Applications/IINA.app`, 1.5.0-beta1 build 170). Source HEAD may differ from that build; the measured 7.5 pt silhouette radius vs source radius 12 is unexplained. Treat source values as the target and re-measure only where listed UNVERIFIED.
